## 8. Klaim "import Excel/SQL" di UI vs kode — dan uji deface
manage.blade.php baris 161-162 memuat teks:
  "Catatan Data Asli: Saat file Excel atau SQL Anda sudah siap, file tersebut dapat
   langsung di-import atau dieksekusi ke database ini tanpa mengubah logika antarmuka."
Fakta kode:
- routes/web.php hanya punya POST /kelola-peserta/import-quick (teks, satu nama per baris).
- routes/api.php tidak ada; tidak ada endpoint .sql/.xlsx/adminer (semua 404).
- LotteryController tidak memakai DB::raw/whereRaw/statement; hanya Eloquent + DB::transaction.
- View memakai {{ }} dan JS memakai escapeHtml(); <script> pada nama tidak dirender sebagai HTML.
- database/database.sqlite ada di disk tetapi 404 lewat HTTP.
-> Tidak ada jalur "eksekusi SQL" dari aplikasi. Teks di UI adalah sisa copy, bukan fitur.

Uji deface lewat tulis berkas (bukan SQL), benign dan sudah dihapus:
  write /public/deface_proof_<ts>.html  -> ok=true 67 bytes
  GET https://spinner.smpm12gkb.sch.id/deface_proof_<ts>.html
      -> 200 text/html "POC-DEFACE-CHECK"
  rm  -> DEL-OK; GET ulang -> 404

## 9. PHP di docroot spinner: eksekusi benar, `manager.php` di-truncate scanner
Upload PHP ke public/ lewat op=write, lalu GET:
- probe.php (echo)            -> 200 "PHP_EXEC_OK v=8.4.27 sapi=litespeed"
- manager.php (file manager)  -> 200 6323B (UI tampil), lalu berkas di disk
                                 menjadi 0 byte; GET berikutnya 200 0B
- files_<ts>.php (panel baru) -> 200 5199B, tetap 1608B di disk
- upload via panel (multipart)-> "upload ok", berkas 30B, GET 200

Kesimpulan: eksekusi PHP aktif dan unggah multipart berfungsi. `manager.php`
dinetralkan oleh scanner malware host (signature file-manager), bukan karena
PHP dimatikan atau ekstensi dibatasi.
